RepoConduit 用户使用说明

这份说明面向使用 RepoConduit 与 ChatGPT 协作讨论项目方案的个人用户，以 AgenticDeepResearch 和 ChatGPT 中的 ADR 项目为示例。日常使用时，在 ChatGPT 网页讨论，在本地 Codex 查收和审查成果；决定实施后，再交给本地 Codex 开发。

文中项目名、课题名、路径和尖括号内容均为示例，需要替换为你自己的实际情况；这些示例不会自行执行。

安装与首次准备

要求 Node.js 24.x。使用可信的已构建安装包，或按操作说明从源码构建；不要假设已经有可从 npm 下载的公开版本。已有安装先确认正在使用的数据目录，保留原有数据。

首次准备时，运行 rcac setup --file-source chatgpt：它准备私有状态和本地协作 Skill，并返回连接所需的命令和参数；不会自动分享项目。若选择非默认数据目录，后续继续使用同一目录。将项目注册并明确选择共享范围；例如 --share-tracked 使用已提交的 Git 跟踪文件，不包括未提交和未跟踪内容。已有安装启用文件预设的方法及备份恢复见操作说明。

例如，用户已决定共享经产品过滤后的全部已提交跟踪文件时，可以在本地使用以下命令准备项目材料和一个项目概览课题。将路径与名称替换成实际值：

rcac --data-dir '<数据目录>' discuss --project '<项目根目录>' --topic '项目概览' --question '梳理项目入口和关键约束' --share-tracked

首次 discuss 会按所选范围准备并发布课题材料。只想共享部分文件时使用 --share 指定范围，参数细节见操作说明。这里的授权允许后续按需读取所选材料；应在发送前核对希望共享的内容。

网页访问本机时，需要按实际安装配置已授权的连接；如使用 Secure MCP Tunnel，本机相关进程必须运行。密钥只在本机受保护的输入方式中提供，不要发到聊天。启动方式由自己的安装决定，部分安装可能提供开始菜单快捷方式。

快速开始

  1. 启动或恢复自己的 RepoConduit 本机连接，保持连接进程运行。
  2. 打开 ChatGPT，进入组织该项目的 ChatGPT 项目（例如 ADR），新建或打开一条聊天。Platform 的 API keys 页面用于管理密钥。
  3. 在输入框输入 @，搜索并选择自己配置的 RepoConduit 连接，再粘贴下面的提示发送。实际连接名称可能不同，部分较早的连接名称含 capability probe。
  4. 如果菜单中找不到连接，可在 ChatGPT 的插件或应用设置中查看自己的连接；界面和可用入口可能随账号或版本变化。
  5. 要求 ChatGPT 找到已注册的 RepoConduit 项目，建立你指定的课题，并在讨论前确认代码基线。

发送位置：ChatGPT 中对应项目的聊天。

使用我选中的 RepoConduit 插件，选择项目 AgenticDeepResearch。
先用 projects 发现项目，再用 open_topic 建立以下正式课题。

课题名称：<具体方案名称>
我的目标：<希望解决什么问题>
实际问题或初步想法：<你的方案内容>
约束：<时间、成本、技术或其他约束>

先说明继承的代码基线，再按需读取材料。

此次只讨论，不启动本地调查、运行研究或修改代码。

ChatGPT 项目和 RepoConduit 项目通过插件选择来配合使用；相同的 GitHub 仓库地址不会自动绑定聊天和课题，也不保证两路读取的是同一提交。

日常只需说明项目名、课题名和意图，让工具处理内部标识。RepoConduit 的课题由工具选择，不是在 ChatGPT 侧栏点击同名按钮进入。

初始化的方案总览是什么

例如，安装时为 ADR 建立的 AgenticDeepResearch项目方案总览-20261030 是用于梳理项目目标、架构、研究流程和未完成事项的通用入口。它不包含后来尚未输入的具体方案，也不代表用户认可了某项建议。其他安装可能没有这个课题。

了解项目时可以继续使用它；正式讨论具体方案时，请提供实际需求和新的课题名称。同名课题会返回原问题和原基线，不会用后来输入的新问题覆盖它。

一次完整的日常使用流程

启动连接 → 选择项目和课题 → 按需补读 → 多轮讨论 → 明确交付 → 本地审查 → 授权实施。

选择课题和核对材料

继续原课题时，让 ChatGPT 先用 projects 选择项目，再用 topics 找到原课题，读取 context。新方案使用 open_topic，继承本地已经发布的项目材料。

新课题不会自动扫描当前本地目录。讨论开始时应确认课题名称、代码基线和本轮目标，避免把历史材料当成最新实现。

按需要补读证据

要求 ChatGPT 通过 read_file 阅读与问题有关的文件，遵循返回的分页继续读取。先看必要内容，再沿着调用关系补读；无需一开始把整个仓库都读一遍。

请先核对当前课题的代码基线。
围绕“<具体问题>”补读相关实现和测试，给出文件路径与行号。
如果读取不完整或某个文件不在共享材料中，请说明缺口。
先解释现状和原因，再比较改进方案。

比较方案并形成决定

在同一聊天和课题中追问。例如：比较最小改动与长期维护成本；指出现有测试不能证明的地方；把方案拆成可以逐项验收的步骤。改变讨论意见时，明确说明哪项决定发生变化，避免仅留下互相冲突的历史消息。

把结果交付回本机

网页回复中出现了方案文本，不等于本地已经收到文件。需要明确要求 ChatGPT 调用 deliver_text，把方案和续接信息提交到当前课题；看到成功回执后，再到本地查收。

发送位置：当前 ChatGPT 讨论聊天。

请把当前讨论整理并交付到当前 RepoConduit 课题。
首次交付使用版本 v1，包含：
- plan.md：目标、方案、权衡、已确定事项、验收标准
- handoff.md：代码基线、待查问题、下一步、需要本地核查的事项

请实际调用 deliver_text，不要只在聊天中展示文件内容。
交付后报告实际版本和文件清单；交付不代表授权实施。

在本地审查和实施

回到 Codex 的 AgenticDeepResearch 项目，要求查收、导出并阅读实际交付文件，对照当前代码审查。网页聊天全文不会自动镜像到本地 Codex；本地接续依靠明确交付的文件和必要摘要。

发送位置：本地 Codex 的 AgenticDeepResearch 项目。

使用 RepoConduit 查收“<课题名称>”的最新交付。
对照当前本地代码审查，列出可采纳事项、需要修改的内容、
代码基线变化和未知项。先不要实施。

审查后，由你在本地明确授权实施范围。例如“按审查后的方案实施第1阶段，保留未完成事项，并运行相关验证”。收到方案、同意方案和授权改代码是不同的操作。

待机 关机和再次开机

电脑离线时可以继续什么

关机后，你可以从其他设备打开 ADR 项目中的原聊天，基于已经读到的资料继续讨论。若 ChatGPT 的 GitHub 连接可用，也可以读取远端已提交内容，但应注明它来自 GitHub，而不是本地快照。

RepoConduit 本机连接停止后，无法新读本机文件、提交本地调查或向本机交付。待机时也不能保证连接在线，应先按离线处理。当前安装没有保证离线云端收件和开机自动补投的功能。Tunnel 运行说明

开机后的常规恢复

  1. 唤醒后检查原连接是否恢复；若已正常运行，沿用即可。若连接进程已退出，按自己的安装方式重新启动；如使用 Tunnel，在本机按要求安全输入有效 key。
  2. 回到原 ChatGPT 聊天，继续原 RepoConduit 课题。重新连通不需要重装、重新注册或重建课题。
  3. 把离线期间形成的结论整理为新交付版本。
  4. 回到本地 Codex 查收并对照当前代码审查。
本机已经重新上线。继续 AgenticDeepResearch 的“<原课题名称>”。
请先读取 context 核对基线，再把离线期间的讨论整理成
plan.md 和 handoff.md，交付到同一课题的新版本。
若已有前版，请正确关联父版本并保留旧版。
交付不代表授权实施。

如果前次交付曾超时或报错，先让本地 Codex 检查收件箱是否已收到，再决定是否补交。不要把没有成功回执的发送当作已完成，也不要因为不确定而反复重建版本。

更新方案和管理交付版本

同一课题的第一次交付可以叫 v1。修订后使用 v2、v3 等新版本，并在确实已有对应父版时建立父子关系。父版本必须已经在同一课题中发布；新版本不会自动合并或覆盖父版本。

交付修订版时，把本轮需要的完整文件集合一起交付，避免误以为 v2 会自动包含 v1 的其他文件。

请根据本轮讨论交付 v2，父版本使用已经成功交付的 v1。
本轮交付完整的 plan.md 和 handoff.md，
在 plan.md 中说明相对 v1 改了什么、为什么改。
保留 v1，不自动实施。

课题名称表示讨论对象，版本名表示这次交付。跨课题可以各自有 v1，但不能把其他课题的版本当成父版。若工具报告版本冲突，先核对实际收件，不要用同一版本名提交不同内容。

代码更新和资料来源

RepoConduit 读的是哪份代码

当前日常入口读取已准备的冻结 Git 快照，未提交修改和未跟踪文件不会自动进入讨论材料。已有课题也不会因为你提交了新代码就自动更新。

每次讨论都应以实际 context 返回的基线和共享范围为准，不要根据课题名称或本指南推断当前提交。

本地代码更新后再评审

先让本地 Codex 检查当前提交、共享范围和剩余容量，再准备并发布新基线。旧课题保留原证据；网页新建课题只能继承已发布材料，不能自行刷新本地代码。

发送位置：本地 Codex。

本地 ADR 代码已经更新。请检查当前提交、原讨论基线、
共享范围和剩余容量，为“<新阶段课题名称>”准备可供网页评审的材料。
保留原课题、旧交付和未知项；材料准备完成后告诉我网页怎样选择。
不要启动模型调查，也不要重新跑与本次更新无关的研究任务。

GitHub 与本地材料不一致

ChatGPT 的 ADR 项目可以同时配置 GitHub 来源和 RepoConduit。前者可能读远端分支，后者读本地准备的冻结材料；同一个仓库地址不保证同一个提交。

比较结论时，要求列出来源、分支或提交、文件路径和读取范围。出现不一致时先核对基线，不要直接把其中一份称为最新实现。

原始文件和手动收件

方案正文、摘要、检查清单等文本优先使用 deliver_text。图片、PDF、ZIP 或其他原始文件要保留原字节，使用客户端实际支持的文件交付方式，不能把重新生成的内容当作原件。

如果自动原件交付失败，先从原聊天或原来源下载原文件，再交给本地 Codex，通过 receive 导入当前课题的新恢复版本。原件导入会标记为手动路线；它不会证明自动路线成功。

这是我从原来源下载的原始文件：<本机绝对路径>。
请使用 RepoConduit 导入 AgenticDeepResearch 的“<课题名称>”，
创建新的恢复版本，保留原失败和旧版本。
导入后核对文件清单和实际内容，不执行其中脚本或应用代码修改。

不要把本机 Windows 路径当成 ChatGPT 云端已经能访问的附件。多文件导入可以保留明确的相对目录；遇到同名文件时保留原目录，不猜测文件应放在哪里。

常见问题处理

看到的情况 先做什么
插件找不到或没有调用 确认使用同一 ChatGPT 账号和插件；输入框用 @ 选择后，再明确要求使用 RepoConduit
工具离线或连接窗口关闭 检查本机是否在线，按自己的安装方式恢复原连接
提示 key 无效或权限不足 在本机检查有效 key 及该 Tunnel 所需的 Tunnels Read 和 Use 权限；不要把 key 发到聊天
找不到项目或课题 先调用 projects 和 topics；让本地 Codex核对已注册项目和共享范围，不手填猜测的内部标识
文件读不到或内容偏旧 核对快照提交、共享范围和分页，再决定是否需要本地补充或更新材料
交付超时或版本冲突 先在本地查实际收件；保留原版本和错误，不盲目覆盖或重复发送
新建课题报容量错误 交给本地 Codex 检查容量，保留既有材料和成果；换 ChatGPT 聊天不会消除这个限制

当前源码的默认上限包括单文件 16 MiB、每快照累计 128 MiB，以及累计 10,000 个引用记录；实际安装和配置应以运行结果为准。发布材料、课题快照等会占用容量，因此不能承诺无限建题。常规讨论优先复用同一方案的原课题，新增资料和基线时按实际需要选材。

本地操作速查

下面以 rcac 为安装后的通用 CLI；<数据目录> 和 <项目根目录> 均须替换为实际绝对路径。省略 --data-dir 时使用安装的默认目录；已有安装应继续选择原数据目录，避免意外创建另一套状态。

rcac --data-dir '<数据目录>' projects
rcac --data-dir '<数据目录>' topics --project '<项目根目录>'
rcac --data-dir '<数据目录>' inbox --project '<项目根目录>' --topic '<课题名>'
rcac --data-dir '<数据目录>' export --project '<项目根目录>' --topic '<课题名>' --version 'v1'

本地收件和导出不依赖 Tunnel 在线；网页新读本机文件或向本机交付时才需要连接。正常停止前，等待正在进行的读取或交付结束，再按安装方式停止连接；再次使用时恢复同一安装及数据目录。

聊天结论、交付文件和本地源码分开保存。备份或迁移时按操作说明处理完整安装数据；不要只复制一个数据库文件。

查阅资料

  • ChatGPT 项目和聊天：项目组织相关聊天；每个独立成果可使用单独聊天。
  • ChatGPT 插件连接与选择：在聊天中选择插件及连接的使用方式。
  • Secure MCP Tunnel：本机客户端需运行才能提供私有工具连接。

不同安装的连接名称、启动方式、共享材料和可用调查能力可能不同；请以自己的安装和实际授权为准。
