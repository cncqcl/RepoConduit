# 主要设计决策

本页汇总对当前实现与验收仍重要的决策；详细历史记录及其原始证据作为私有资料保留。具体合约以[架构与合约](ARCHITECTURE_AND_CONTRACTS.md)、[产品设计](../DESIGN.md)和 `contracts/` 为准；验证结论见[验证状态](release-evidence.md)。

1. **统一应用 handler。** 所有入口经同一应用处理授权、副作用和状态。适配器转换协议，不复制业务权限或绕过 dispatch。
2. **固定证据快照。** 重要评审绑定上下文、快照及其范围；记录未提交内容、排除项、分页与证据 hash。HEAD 或文件时间不变不能证明整个仓库一致。
3. **显式项目身份与隔离。** 不存在隐含的全局当前工作区；项目、讨论、工作副本和授权按各自身份解析与检查。撤权、并发和跨项目读取都要保持边界。
4. **调查与实施分离。** 外部参与者只获得明确的证据读取、受限调查请求与收件能力；不能获得任意命令、源码写入、git commit、部署或任意权限修改。调查需核验隔离、路径、预算和当前授权，默认不隐含开启。
5. **交付、审查、采纳和实施分别记录。** 网页回复不是交付，交付不自动采纳；实际源码实施仍由本地用户授权。人工接管和恢复要保留实际会话绑定及未知发送状态。
6. **完整版本化交付。** 文件集与 manifest 完整发布，版本及父版本不覆盖；不将部分成功、缺失原件或不同版本组件拼成完整 bundle。
7. **原件与 route 可追溯。** 平台文件、授权本地收取和手动导入分别记录，保留原字节、失败与 UNKNOWN；手工恢复不改写为自动路线成功。
8. **D237 有界批次。** 围绕同一实际场景汇总修复和去重验证，保留局部复现；不重复运行不受影响的范围，也不降低必要的安全、集成和发布关卡。详见[实施计划](IMPLEMENTATION_PLAN.md)。
9. **先完成首个组合，保留完整标准。** Codex 与 ChatGPT 是当前首要个人使用组合；第二运行时后置，不将其未完成状态视为完整中立性或 `release_ready` 通过。
10. **MIT 源码与私有证据分离。** 项目源码采用 [MIT](../LICENSE)。历史真实操作的日志、回执和其他含个人信息的材料保留为私有证据；公开摘要不能替代原始证据，也不因公开源码改变验收结果。第三方声明另行保留。
